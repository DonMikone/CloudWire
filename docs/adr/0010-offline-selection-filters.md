# Offline Items mirror their root and sync a Selection via bisync filters

An Offline Item picked in the checkbox tree is rooted at the Connection root; its Storage Location mirrors that root, so every checked folder and file sits at its full cloud path. One item holds the whole Selection, stored as `kind files` with nested paths (`kind folder` when the root itself is checked). The Core turns each entry into anchored include rules, `+ /p` and `+ /p/**`, followed by `- **`. rclone derives directory includes for the parents, so parent folders are traversed but kept as structure only: their own files and unchecked subfolders are not synced, while a checked folder includes later additions.

Changing a filter never deletes anything by itself, and bisync must not treat a deselected part as a local deletion. Changing the Selection therefore writes the new filters and forces a resync before the item runs again, and moves the deselected local copy to the Trash or keeps it, as the user chooses. The cloud is never touched. Items created before 0.3.0 keep their folder as root and work unchanged. Their Storage Location may lie inside a new item's Storage Location when it sits exactly at its cloud path there (the default layout), because the remote paths of two items never overlap and each item syncs only its own part; the innermost item owns a local path for Finder badges and actions.

Considered: one Offline Item per checked folder. Rejected because a Selection would split into many items, items of a parent and its child cannot overlap, and the Selection could not be edited as one.
