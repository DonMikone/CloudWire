# Offline Items mirror their root and sync a Selection via bisync filters

An Offline Item picked in the checkbox tree is rooted at the Connection root; its Storage Location mirrors that root, so every checked folder and file sits at its full cloud path. One item holds the whole Selection, stored as `kind files` with nested paths (`kind folder` when the root itself is checked). The Core turns each entry into anchored include rules, `+ /p` and `+ /p/**`, followed by `- **`. rclone derives directory includes for the parents, so parent folders are traversed but only partially selected: a checked folder includes later additions from both sides, while unchecked content of a parent folder is not synced.

What the user creates locally inside a partially selected folder joins the Selection automatically (the Core scans for it on every run and on watcher events), so nothing placed in the mirror stays local-only and a local rename of a checked folder becomes a rename in the cloud instead of a cloud deletion. System and temporary files and conflict copies never join. What appears only in the cloud inside a partially selected folder stays cloud-only, so a new cloud folder never triggers an unwanted large download.

Changing a filter never deletes anything by itself, and bisync must not treat a deselected part as a local deletion. Changing the Selection therefore writes the new filters and forces a resync before the item runs again, and always moves the deselected local copy to the Trash; the cloud is never touched. Keeping a deselected local copy is not offered, because it would sit in a partially selected folder and join the Selection again. Items created before 0.3.0 keep their folder as root and work unchanged. Their Storage Location may lie inside a new item's Storage Location when it sits exactly at its cloud path there (the default layout), because the remote paths of two items never overlap and each item syncs only its own part; the innermost item owns a local path for Finder badges and actions.

Considered: one Offline Item per checked folder. Rejected because a Selection would split into many items, items of a parent and its child cannot overlap, and the Selection could not be edited as one. Considered: an exclusion model (a partially selected folder syncs everything but deselected children). Rejected because every new cloud folder would download.
