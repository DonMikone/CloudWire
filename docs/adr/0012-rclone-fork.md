# rclone is a locally patched fork under core/third_party/rclone

CloudWire links rclone in-process (ADR 0003), and two bisync defects made Offline Items unrecoverable: `--recover` validates its backup listings byte-exact while the AliasMap is still empty, so a local NFD name never matches its cloud NFC twin and every recovery after a critical abort fails with "path1 and path2 are out of sync" forever; and `WhichEqual` reports "not equal" when no hash is available (a webdav object uploaded by another client without `oc:checksums`), aborting every `--resync` with "Unable to rollback during --resync" and leaving it in a resync loop. A third defect crashed every run: when a directory is new on both sides as normalization twins (local NFD, cloud NFC), `applyDeltas` looks the Path2 listing up by the Path1 name, gets nil and panics ("invalid memory address or nil pointer dereference"); the rc job recovers the panic, but the lock file stays behind, so the following runs fail with "prior lock file found" until `--max-lock` expires and the next run panics again. All three exist in rclone v1.75.x and master. rclone is therefore vendored as an unpruned subtree of v1.75.1 with four patches (`cmd/bisync/operations.go` `fillAliasesFromListings`, `cmd/bisync/checkfn.go` `noHashEqual`, `cmd/bisync/deltas.go` alias lookup for directories new on both sides, `cmd/bisync/operations.go`/`lockfile.go` `releaseAfterPanic`), pulled in via a `replace` directive in `core/go.mod`; the sync engine additionally escalates retry delays on consecutive failures so no future failure class can loop at full rate (1, 2, 5, 15, 30 minutes), and reports a recovered panic as its own translatable error instead of the raw panic text.

Consequences: an upstream upgrade means reapplying the four patches — every patch carries a `// CloudWire patch (see docs/adr/0012):` marker and the fork README lists them; the vendor tree must move together with `core/go.mod`'s `replace` line; unit and integration tests pin the patch behaviors (`cmd/bisync/checkfn_test.go`, `cmd/bisync/lockfile_test.go` `TestReleaseAfterPanicFreesLockAndMarksListingsFailed`, `TestRecoverAfterNormalizationMismatch`, `TestNormalizationTwinDirsNewOnBothSides`), the panic error state (`TestErrorReason`, `TestPanickedRunRetriesWithBackoff`) and the backoff (`TestFailedRunsBackOff`). Upstream issues for the defects are filed by CloudWire; linked once the fork is published.

Considered: waiting for upstream fixes. Rejected because the Nextcloud item had been failing every minute for days and both defects sit in rclone's own documented workflow (`--recover`, `--resync`). Considered: `--size-only` or `--ignore-checksum` flags per item. Rejected because they weaken equality checks globally instead of only where no hash exists. Considered: forking via GitHub PR upstream first. Rejected for the local item: in-process linking needs the fix now; the upstream PR follows from the same patches.
