# Local wins unless a Cloud Change is proven

On 2026-11-02 a Logic Pro session on a single Mac produced 577 Conflict Copies and lost comped bass regions, although nothing but CloudWire touched the cloud: aborted bisync runs left the listings without CloudWire's own last uploads, `--recover` fell back to older listings, and bisync took CloudWire's own uploads for changes in the cloud ("changed on both sides"); `resyncMode newer` then let older cloud content win over a local file that Logic had saved with an older modtime. We decided that a cloud version may overwrite or delete a local file only on a proven Cloud Change — a cloud state that differs from the last state CloudWire itself wrote or read for that path, recorded per file outside bisync's run-scoped listings so aborts cannot erase it. Without that proof the local version wins silently, with no Conflict Copy.

Details: proof is a per-file transfer journal in the bisync fork (a marked patch per ADR 0012), written right after each confirmed transfer in either direction with the cloud ETag, size and modtime; a differing current cloud state is a Cloud Change, a failed or aborted transfer (including rclone's removal of a `sha1 differ` upload) leaves no entry and is retried. The rule governs normal runs, `--recover`, expired locks and `--resync` alike; `resyncMode newer` is dropped. Local change plus proven Cloud Change keeps the local file and saves the cloud version as Conflict Copy; a proven cloud deletion of an unchanged local file moves it to the macOS Trash, as does any local file a cloud version replaces. A new Offline Item has no history, so on its first sync a file that differs on both sides keeps the local version and gets a one-time Conflict Copy; existing items migrate by seeding the journal from files equal on both sides, the rest count as unproven.

Consequences: around this rule, files that change during a transfer are skipped and retried instead of aborting the run; CloudWire's own writes (`.partial` renames, Conflict Copies) and local deletions never interrupt a running sync, and deletions no longer skip the Quiet Period; Logic's `Alternatives/*/Autosave/` and comparable DAW autosave folders are excluded by default; Studio Mode is on by default when a known DAW is installed, a starting DAW or sleep stops a run cleanly (in-flight transfer aborted, completed ones recorded), and Core updates wait while a run or a DAW is active. Acceptance is end-to-end against Nextcloud (`scripts/e2e-nextcloud.sh`): a file growing during upload, Logic-like autosave churn, kill mid-run then recover, and a resync with newer local content under an older modtime create no Conflict Copy; a foreign Cloud Change still arrives locally; a proven cloud deletion lands in the Trash.

Considered: keep "changed on both sides → Conflict Copy" and only remove the causes of aborts. Rejected because any future listing loss would again turn CloudWire's own uploads into conflicts. Considered: local wins but a Conflict Copy whenever proof is missing. Rejected because it floods projects with copies of the user's own older files, which is what made the incident unreadable.
